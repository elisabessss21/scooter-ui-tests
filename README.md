# Финальный проект 6-го спринта — Яндекс.Самокат

Учебный Maven-проект автотестов UI сервиса https://qa-scooter.education-services.ru/.

## Требования к окружению

- **Java 11** (в `pom.xml` указано `maven.compiler.release=11`)
- **Maven**
- **JUnit 5** и **Selenium 4**
- Установленный **Google Chrome** и **Mozilla Firefox** для локальных запусков

## Структура

```
src/
  main/java/ru/praktikum/scooter/pages/
    MainPage.java          # Главная страница, обе кнопки заказа, FAQ
    OrderPage.java         # Первый шаг оформления заказа
    RentPage.java          # Второй шаг, подтверждение и успешное оформление
  test/java/ru/praktikum/scooter/
    BaseTest.java          # Создание WebDriver, driver.quit() в @AfterEach
    FaqTest.java           # 8 параметризованных проверок
    OrderTest.java         # 4 параметризованных проверки заказа
```

В Page Object комментарий с названием элемента идёт непосредственно перед его локатором, как требуется в задании.

## Что проверяют тесты

1. Раскрытие каждого из восьми ответов FAQ и характерный текст соответствующего ответа.
2. Позитивный сценарий оформления заказа с **двумя наборами данных**.
3. Каждая из **двух кнопок «Заказать»** проверяется с обоими наборами (всего 4 запуска).
4. Финальный результат — видимый заголовок «Заказ оформлен» после подтверждения.
5. Браузер завершается с `driver.quit()` после *каждого* запуска теста, в том числе упавшего.

Итого **12 параметризованных запусков**: 8 FAQ + 4 заказа. Факультативные тесты на логотипы, валидацию и неверный номер заказа не включены.

## Импорт проекта в IntelliJ IDEA

1. Распакуйте ZIP.
2. В IntelliJ IDEA выберите **File → Open** и откройте папку `scooter-ui-tests`, где расположен `pom.xml`.
3. В **File → Project Structure → Project SDK** выберите JDK 11 (при необходимости установите её).
4. Обновите Maven-проект (кнопка **Reload All Maven Projects**).
5. Запускайте тесты из классов `FaqTest` / `OrderTest` или командами ниже.

## Запуск

```bash
mvn clean test -Dbrowser=chrome
mvn clean test -Dbrowser=firefox
mvn test -Dtest=FaqTest -Dbrowser=chrome
mvn test -Dtest=OrderTest -Dbrowser=firefox
```

По умолчанию используется Chrome. Selenium Manager из Selenium 4 обычно самостоятельно подбирает подходящий драйвер для установленного браузера.

## Соответствие шпаргалке «Тестирование веб-приложений»

Использованы конструкции, разобранные в учебном материале:

- локаторы `By.id`, `By.xpath`, `By.cssSelector`, `By.className`;
- `findElement()`, `click()`, `sendKeys()`, `getText()`;
- явные ожидания `WebDriverWait` и `ExpectedConditions`;
- прокрутка к элементу с `JavascriptExecutor`;
- Page Object Model: локаторы и методы действий — в классах страниц, проверки — в тестах;
- `driver.quit()` после тестов.

**Важно:** в некоторых примерах шпаргалки приведён JUnit 4 (`@After`, `org.junit.Test`) и старый синтаксис `WebDriverWait(driver, 3)`. В проекте **осознанно** применены JUnit 5 (`@AfterEach`, `@ParameterizedTest`) и Selenium 4 (`Duration.ofSeconds(...)`), как требует задание и используемые версии библиотек.

## Ограничения проверки

Код и структуру можно проверить локально в IDE, но перед сдачей обязательно выполните тесты в реальном браузере: доступная среда сборки не содержала Maven и не имела доступа к приложению по сети.

Особенно проверьте актуальность HTML-локаторов `Home_FinishButton`, `Order_Buttons`, выбора метро и календаря, а также ожидаемых ответов FAQ — они взяты из типичной разметки учебного сайта и требуют подтверждения на текущей версии приложения. Известный баг Chrome нельзя маскировать в коде: падение автотеста из-за неисправности приложения — корректный результат проверки.
